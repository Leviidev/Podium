# Podium

Podium is a native iOS/iPadOS app working toward running a genuine iOS 6.1.6
environment by emulating the iPod touch (4th generation).

**Podium does not boot iOS yet.** This is early, foundational work: a
polished SwiftUI frontend, a real IPSW parser, and a modular emulator
architecture with clean protocol boundaries — CPU, memory, MMU, interrupts,
timers, storage, display, input, audio, and networking are each their own
module, none of them faked as working. The app is always honest in the UI
about what's actually implemented versus planned.

## Target hardware

| | |
|---|---|
| Device | iPod touch (4th generation) — `iPod4,1` |
| Firmware | iOS 6.1.6, build `10B500` |
| CPU | Apple A4 (ARMv7) |
| Display | 960×640 |
| RAM | 256 MB |

## What's implemented

- **Firmware import & inspection** — imports an `.ipsw`, validates it as a
  real ZIP archive (hand-rolled reader, no third-party dependency), reads
  `BuildManifest.plist`, and reports the actual device/iOS version/build it
  finds — never trusting the file name. Imported firmware is always a copy;
  Podium never modifies the user's original file.
- **Compatibility detection** — strict match against the one firmware
  Podium currently targets (`iPod4,1` / 6.1.6 / `10B500`), with plain-language
  errors and technical detail tucked behind a "Details" disclosure.
- **Emulator module architecture** — `CPU`, `MemoryBus`, `MMU`,
  `InterruptController`, `TimerController`, `VirtualStorageDevice`,
  `FramebufferSource`, `InputController`, `AudioOutput`, `NetworkInterface`:
  all protocols, injected via dependency injection rather than hardcoded to
  a concrete type. A bounds-checked flat physical memory implementation
  exists and is tested; there is no CPU yet.
- **Honest status reporting** — the emulator screen shows a real, aspect-
  correct placeholder and whatever `EmulatorCore`'s actual status is
  (currently always "Emulator core not implemented"). Podium never fakes a
  boot sequence.

## What's not implemented yet

CPU execution, MMU translation, interrupts/timers, guest storage, a real
framebuffer, audio, and networking are all unimplemented — see
`Podium/Emulator/`. The roadmap works through these as: get a CPU
decoding/executing instructions, get the kernel executing, then expand
hardware support until userspace and SpringBoard are reachable.

## Project layout

```
Podium/
├── App/            Entry point, root DI wiring
├── UI/              SwiftUI screens (Main, Firmware, Settings, Emulator)
├── Firmware/        IPSW/ZIP parsing, compatibility, on-disk storage
├── Emulator/        CPU, Memory, MMU, Interrupts, Timers, Storage,
│                     Display, Input, Audio, Network
├── Rendering/       Display pipeline (placeholder today; Metal later)
└── Shared/          Cross-module utilities
PodiumTests/          Firmware parsing + memory unit tests
```

## Building

```
xcodegen generate
open Podium.xcodeproj
```

Requires Xcode 16+. The `.xcodeproj` is generated by
[XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml` and is
not committed.
